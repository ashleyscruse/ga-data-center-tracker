# Update Guide

How to regenerate the dataset, so it can be refreshed in future years without
starting over. Written for a maintainer who did not build the pipeline.

## Setup (once)

```bash
# From the repository root, in a virtual environment:
python -m venv .venv && source .venv/bin/activate
pip install -e .            # installs the package and its dependencies
# Optional, for notebook analysis:
pip install -e ".[analysis,dev]"
```

## Rebuild the county reference table

The reference table (`data/reference/ga_counties.csv`) rarely changes, but to rebuild
it from the authoritative Census source:

```bash
python -m ga_data_center_tracker.counties
# or, after install:
gdct-build-counties
```

This refuses to write unless it finds exactly 159 Georgia counties, guarding against
a changed upstream file.

## Run the full pipeline

```bash
python -m ga_data_center_tracker.pipeline --out data/processed/ga_data_centers.xlsx
```

The output is a Solutions Tracker `.xlsx` workbook (see [output_format.md](output_format.md)).

For a quick test run that only does a handful of network lookups:

```bash
python -m ga_data_center_tracker.pipeline --max-lookups 50 --out /tmp/test.xlsx
```

## What lives where

| Path | Tracked in git? | Contents |
|---|---|---|
| `data/reference/` | Yes | County reference table (committed). |
| `data/processed/` | Yes | Final deliverable dataset (committed). |
| `data/raw/`, `data/interim/` | No (gitignored) | Scraped and intermediate data, regenerated by the pipeline. |
| `_admin/`, `_planning/` | No (gitignored) | Contracts, budget, planning notes. |

## Refreshing a single source

Each source is a module under `src/ga_data_center_tracker/scrapers/`. To refresh one
source in isolation, call its scraper directly; for example:

```python
from ga_data_center_tracker.scrapers import epa_frs
records = epa_frs.scrape_georgia_data_centers()
counts = epa_frs.records_to_county_counts(records)
```

## Adding a new source

1. Write a scraper module in `scrapers/` that returns typed records and exposes a
   `..._to_county_counts()` aggregator (follow `epa_frs.py` as the template).
2. Document the source in [sources.md](sources.md) and its variables in
   [data_dictionary.md](data_dictionary.md).
3. Wire it into `pipeline.py`: merge its per-county counts into `county_values` and
   add its `Variable` entries.
4. Add tests under `tests/`.
